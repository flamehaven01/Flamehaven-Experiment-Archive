# Playbook — BSC Lane (Bioscience Compliance)

> Lane playbook, loaded **on_demand** when working on BSC scans (`bsc/[repo]/[date]/`).
> Shared protocols (API build, OPSEC sanitizer, UI/UX SDK) live in [`playbook-common.md`](./playbook-common.md).
> DI namespace: `DI-BSC-*`. Index: [`verification-ledger-playbook.md`](./verification-ledger-playbook.md).

Bioscience Compliance — static, zero-execution safety scans of public bioscience AI repositories, mapped to the MIT AI Risk Repository (AIRI) tier classification (T0 Rejected → T3 Clear).

---

## 3.0 Operating Rules

- **Compliance Scans**: Audits must search for clinical hazard surfaces and map outcomes against standard risk repositories.
- **Report Generation**: Scans must generate standalone HTML, Markdown, and JSON results under `bsc/[repo]/[date]/`.
- **Portal Integration**: Every card must present circular gauge metrics, stage-by-stage rating bars, and detailed Selection & Evaluation briefs.

---

## 3.1 Registry-Driven Card Pattern (DI-BSC-001)

BSC cards are **not** hardcoded in `index.html`. They are auto-generated from `js/bsc-registry.js` by `bsc-renderers.js` on `DOMContentLoaded`. `index.html` never changes for new entries.

**To add a new BSC audit:** add one object to `BSC_REGISTRY` in `js/bsc-registry.js`. The renderer picks it up automatically.

**Inspector wiring (REQUIRED for the bottom Ledger Inspector to work):** the inspect button calls `openJsonInspector(c.id)`. For that id to render, add it to THREE branches in `js/portal-inspector.js`: (1) the `jsonPath` resolver, (2) the BSC insights branch (`runId === 'yorkeccak-bio' || ... || '<id>'`), (3) the `code_integrity` bridge. The scan `experiment_results.json` must carry the BSC schema (`score.final_score`, `score.formal_tier`, `score.use_scope`, `code_integrity`, `file_hashes_sha256`). Also confirm `_bscTierColor` in `portal.js` maps the entry's tier prefix (T0→red, T1→orange, T2→amber).

**Inline onclick quoting (DI-SDK):** card `onclick="openReportViewer(...)"` args must be **single-quoted** JS literals (the card uses a `sq()` helper), never `JSON.stringify` — double quotes terminate the double-quoted attribute and throw `Unexpected end of input` reported at the HTML EOF line. The sidebar/hash-nav paths attach handlers as function refs and are safe; the card button is the exposed one.

**Slot mechanism** (`slot: true`): Pre-registers an entry whose artifact files are not yet in the repo. The fix for "files not uploaded" is to PLACE the sanitized files, not to ship a permanently-blocked card. Slot effects (must be honored in ALL renderers — card body AND sidebar):
- Card title is plain text (no viewer link); PENDING badge in the eyebrow
- Open Report / Inspect / PDF / MD / JSON buttons disabled (`dl-btn-slot` class)
- Sidebar entry non-clickable (`pointer-events:none`)
- Article / Newsletter buttons activate independently if their URL fields are set (they may be live on flamehaven.space before repo artifacts exist)
- **Activation**: when files are placed + sanitized, remove `slot` and set `articleUrl` / `newsletterUrl`

**Newsletter button** (`newsletterUrl` field): button type `dl-btn-newsletter` (cyan `#06b6d4`). Renders when the `newsletterUrl` key is **present** (even if null). `null` = visible but disabled; string URL = active link. Older entries without the key show no button.

**Version bump rule**: after ANY change to `bsc-registry.js`, `bsc-renderers.js`, `portal-inspector.js`, or `portal.js`, bump the `?v=X.Y.Z` cache-buster on all script tags in `index.html`. Without it browsers serve stale cached JS despite a deployed fix.

## 3.2 Regulatory Reference Registry

**Source of truth:** `STEM-BIO-AI/docs/regulatory_basis_registry.v1.json` — auto-generated by `STEM-BIO-AI/tools/update_regulatory_registry.py`. Do not edit the JSON manually.

**Active frameworks** (as of Jun 2026):

| ID | Display label | Source |
|---|---|---|
| `eu_ai_act_2024_1689` | EU AI Act (Regulation (EU) 2024/1689) | `STEM-BIO-AI/references/_registry_entries/` |
| `fda_qmsr` | FDA QMSR | same |
| `fda_mlmd_transparency_2024` | FDA ML-MD Transparency (2024) | same |
| `fda_pccp_2025` | FDA PCCP (2025) | same |
| `imdrf_samd_clinical_eval_2017` | IMDRF SaMD Clinical Eval (2017) | same |
| `imdrf_gmlp_2025` | IMDRF GMLP (2025) | same |
| `ich_m15_midd_2026` | **ICH M15 MIDD (Step 4, Jan 2026)** | `STEM-BIO-AI/references/M15 General Principles...md` |

> **Step vs Sep rule:** ICH adoption milestones must be written **"Step 4, Jan 2026"** — not "Step 4" alone — to prevent misreading as "Sep 4" (September 4). Enforced via `display_label` in the YAML entry.

**Regulatory update workflow (cross-repo):**

```
1. Convert PDF → MD                STEM-BIO-AI/references/<id>.md       (user)
2. Create/update YAML              STEM-BIO-AI/references/_registry_entries/<id>.yaml
3. Run update script               python STEM-BIO-AI/tools/update_regulatory_registry.py
4. If new requirement_id needed    update STEM-BIO-AI/stem_ai/regulatory_traceability.py
5. Re-run BSC scanner              reports in flamehaven-audit-reports/bsc/ auto-update
```

**Deprecation:** set `status: superseded` + `superseded_by: <new_id>` in the YAML. Never delete — old reports reference the ID. Re-run the script.
